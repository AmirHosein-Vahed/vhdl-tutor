# 01 — ROM و ثابت‌های مقدارگذاری‌شده

**وضعیت:** برنامه‌ریزی‌شده · **موضوع:** [07-memories — حافظه‌ها](../README.fa.md) · [English](README.md)

> این درس هنوز نوشته نشده است. هدف، مفاهیم و تمرین‌های زیر قرارداد آن هستند
> و کد هنگام تکمیل موضوع اضافه می‌شود.

## هدف

یک ROM را از تابع یا فایل مقداردهی کن و بفهم چرا ROM نباید ریست داشته باشد.

## از وریلاگ به VHDL

| Verilog / SystemVerilog | VHDL |
|---|---|
| `initial $readmemh(...)` | `constant ROM : rom_t := (...);  -- elaboration time` |

## مفاهیم

- type rom_t is array (0 to N-1) of std_logic_vector(7 downto 0); constant ROM : rom_t := (...).
- یک تابع می‌تواند ضرایب (سینوس، لگاریتم) را در زمان بسط تولید کند.
- ریست‌کردن ROM اشتباه است: بلوک RAM را به منطق تبدیل می‌کند و محتوای اولیه را از بین می‌برد.

## اجرا

```bash
make        # تحلیل، بسط و اجرای بستر آزمون خودبررسی
make wave   # همان، به‌همراه باز کردن شکل موج در Surfer یا GTKWave
make clean  # پاک کردن build/
```

## تمرین‌ها

1. با یک تابع جدول سینوس ۲۵۶ عضوی بساز و سه مقدار را در بستر آزمون بررسی کن.
2. همان جدول را با textio از فایل بخوان و دو ROM را مقایسه کن.
