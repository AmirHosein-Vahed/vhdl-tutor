# 02 — بازنویسی یک ماژول وریلاگ در VHDL

**وضعیت:** نوشته‌شده · **موضوع:** [00-hello-world — سلام، دنیا](../README.fa.md) · [English](README.md)

> این درس آماده است. در همین پوشه `make` را اجرا کن تا طراحی مرجع ساخته شود،
> بستر آزمون خودبررسی اجرا شود و در صورت شکست کد خروج غیرصفر برگردد.

## هدف

ماژولی را که از قبل می‌فهمی ترجمه کن و از تفاوت‌ها سه چیز را یاد بگیر که VHDL صریح بیان می‌کند: بندهای زمینه، جدایی موجودیت از معماری، و انواع حل‌شده.

## از وریلاگ به VHDL

| Verilog / SystemVerilog | VHDL |
|---|---|
| `parameter W = 8` | `generic (W : positive := 8)` |
| `always @(posedge clk)` | `process (clk) begin if rising_edge(clk) then ...` |

## مفاهیم

- عبارت library ieee; use ieee.std_logic_1164.all; یک بند زمینه است — VHDL هیچ چیز را به‌صورت خودکار وارد نمی‌کند.
- رابط و پیاده‌سازی در دو ناحیهٔ اعلان جدا هستند، پس یک موجودیت می‌تواند چند معماری داشته باشد.
- std_logic یک نوع ۹مقداریِ حل‌شده است؛ std_logic_vector آرایه‌ای از آن است و تا وقتی نگویی، عدد نیست.

## فایل‌ها

| فایل | نقش |
|---|---|
| `src/counter.vhd` | the translated module, one entity + one architecture |
| `tb/counter_tb.vhd` | checks reset and three counts |

## اجرا

```bash
make        # تحلیل، بسط و اجرای بستر آزمون خودبررسی
make wave   # همان، به‌همراه باز کردن شکل موج در Surfer یا GTKWave
make clean  # پاک کردن build/
```

## چه چیزی را ببینیم

تعداد خطوط src را با معادل وریلاگی مقایسه کن: VHDL خطوط را صرف اعلان‌ها می‌کند و در عوض صراحت می‌خرد. generic جای parameter را می‌گیرد؛ تقسیم‌بندی reg/wire وجود ندارد — فقط سیگنال و متغیر داریم.

## تمرین‌ها

1. یک generic به نام MAX با مقدار پیش‌فرض ۱۵ اضافه کن و کاری کن شمارنده به‌جای 2**W-1 در MAX بچرخد.
2. معماری دومی به نام behavioural برای همان موجودیت بنویس که از متغیر به‌جای سیگنال استفاده می‌کند و آن را در بستر آزمون انتخاب کن.
