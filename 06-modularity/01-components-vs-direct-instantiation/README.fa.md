# 01 — کامپوننت در برابر نمونه‌سازی مستقیم

**وضعیت:** برنامه‌ریزی‌شده · **موضوع:** [06-modularity — پیمانه‌ای‌سازی](../README.fa.md) · [English](README.md)

> این درس هنوز نوشته نشده است. هدف، مفاهیم و تمرین‌های زیر قرارداد آن هستند
> و کد هنگام تکمیل موضوع اضافه می‌شود.

## هدف

یک موجودیت را به هر دو روش نمونه‌سازی کن و مرحلهٔ اتصالی را بفهم که فقط کامپوننت دارد.

## از وریلاگ به VHDL

| Verilog / SystemVerilog | VHDL |
|---|---|
| `foo u (.a(a), .y(y));` | `u : entity work.foo port map (a => a, y => y);` |

## مفاهیم

- ‎u : entity work.foo port map (...) در بسط اتصال می‌یابد و پیش‌فرض مدرن است.
- اعلان کامپوننت اتصال را به پیکربندی واگذار می‌کند — برای تعویض معماری مفید است.
- اتصال نام‌دار (a => sig_a) یک ضرورت است؛ اتصال موقعیتی بی‌صدا می‌شکند.

## اجرا

```bash
make        # تحلیل، بسط و اجرای بستر آزمون خودبررسی
make wave   # همان، به‌همراه باز کردن شکل موج در Surfer یا GTKWave
make clean  # پاک کردن build/
```

## تمرین‌ها

1. معماری DUT را در بستر آزمون بدون دست‌زدن به نمونه‌سازی عوض کن.
2. یک اتصال موقعیتی را خراب کن و ببین خطا چقدر دیر ظاهر می‌شود.
