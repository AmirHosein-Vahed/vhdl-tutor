# 11-verification — چارچوب‌های راستی‌آزمایی

**وضعیت:** 0 از 3 درس نوشته شده · [نقشهٔ راه](../../README.fa.md) · [English](README.md)

## چرا این موضوع

اختیاری اما مسیرساز: VUnit و OSVVM و cocotb بسترهای آزمون دستی را به مجموعهٔ رگرسیون تبدیل می‌کنند. این موضوع شکل هر کدام را نشان می‌دهد، نه یک دورهٔ کامل.

## از وریلاگ به VHDL

| Verilog / SystemVerilog | VHDL |
|---|---|
| `// no framework` | `uv run python run.py` |
| `$urandom_range(0, 15)` | `RandInt(0, 15)` |
| `assert property (@(posedge clk) req \|-> ##[1:4] ack);` | `-- psl assert always req -> eventually[1 to 4] ack;` |

## درس‌ها

| # | درس | هدف | وضعیت |
|---|---|---|---|
| 01 | [مبانی VUnit](01-vunit-basics/README.fa.md) | یک بستر آزمون دستی را به بستر VUnit تبدیل کن، دو مورد آزمون ثبت کن و با python run.py اجرا کن. | برنامه‌ریزی‌شده |
| 02 | [OSVVM و تصادفی‌سازی](02-osvvm-and-randomization/README.fa.md) | از بستهٔ تصادفی OSVVM استفاده کن تا به حالت‌های گوشه‌ای برسی که بردارهای دستی هرگز نرسیدند. | برنامه‌ریزی‌شده |

## پس از این موضوع می‌توانی

- اجرای مجموعهٔ آزمون VUnit از خط فرمان
- استفاده از تصادفی‌سازی مقید و مفهوم scoreboard
- نوشتن ویژگی PSL که GHDL بررسی‌اش کند

## پیش‌نیاز

ابتدا موضوع قبلی را تمام کن؛ هر موضوع مستقیماً روی قبلی ساخته می‌شود.
درس اول کل زنجیرهٔ ابزار را هم توضیح می‌دهد، بنابراین پیش‌زمینهٔ VHDL لازم نیست.
