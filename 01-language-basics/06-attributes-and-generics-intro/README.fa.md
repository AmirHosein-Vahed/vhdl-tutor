# 06 — ویژگی‌ها و جنریک‌ها

**وضعیت:** نوشته‌شده · **موضوع:** [01-language-basics — مبانی زبان](../README.fa.md) · [English](README.md)

> **آماده.** در همین پوشه `make` را اجرا کن. طراحی `param_counter` ساخته
> می‌شود، بستر آزمون خودبررسی اجرا می‌شود و در صورت شکست کد خروج غیرصفر
> برمی‌گردد.

## هدف

به‌جای عدد جادویی از ویژگی استفاده کن و به‌جای ویرایش ثابت‌ها پیش از هر ساخت،
از جنریک. یک موجودیت، دو عرض، دو شمارش پایانی، بدون کپی‌پیست.

## از وریلاگ به VHDL

| وریلاگ / SystemVerilog | VHDL |
|---|---|
| `parameter WIDTH = 8;` | `generic (WIDTH : positive := 8);` |
| `#(.WIDTH(16), .MAX(1000))` | `generic map (WIDTH => 16, MAX => 1000)` |
| `$bits(v)`، `$high(v)` | `v'length`، `v'high`، `v'low` |
| `$size`، `$left`، `$right` | `'length`، `'left`، `'right`، `'range`، `'image` |
| `localparam` | `constant` در معماری |

جنریک‌ها مقادیر زمان بسط‌اند: عرض درگاه، کران آرایه، ثابت‌ها و رفتار
زیربرنامه‌ها را تعیین می‌کنند. ورودی زمان اجرا نیستند.

## مفاهیم

- جنریک پارامتر موجودیت است. `generic map` آن را برای هر نمونه بازنویسی
  می‌کند، پس دو نمونه از یک موجودیت می‌توانند دو مدار کاملاً متفاوت باشند.
- `'length`، `'high`، `'low`، `'left`، `'right` و `'range` ویژگی‌هایی‌اند که
  یک سیگنال، متغیر یا نوع را توصیف می‌کنند. کد را مستقل از ابعاد نگه می‌دارند.
- `'image` مقدار را به رشته تبدیل می‌کند؛ روش چاپ عدد در گزارش‌های VHDL
  بدون قالب‌بندی سبک `$display`.
- تابعی که در ناحیهٔ اعلان معماری اعلان شود می‌تواند جنریک‌ها را بخواند.
  `terminal_count` در زمان بسط اجرا می‌شود و `MAX` جنریک را به `unsigned` با
  عرض `WIDTH` تبدیل می‌کند.
- `MAX = 0` یک نشانگر است: یعنی «در بیشینهٔ طبیعی، `2**WIDTH - 1`، بپیچ». یک
  شمارش پایانی واقعی از `MAX >= 1` استفاده می‌کرد.
- `(others => '0')` برای هر عرضی کار می‌کند، پس منطق ریست و پیچش هرگز به
  `WIDTH` اشاره نمی‌کند.
- انتساب نام‌دار (`WIDTH => 4, MAX => 9`) خودتوضیح و مستقل از ترتیب است.
  انتساب موقعیتی قانونی است اما با افزودن یک جنریک به‌راحتی می‌شکند.

## اجرا

```bash
make        # تحلیل، بسط و اجرای بستر آزمون خودبررسی
make wave   # همان، به‌همراه نوشتن build/param_counter_tb.ghw
make clean  # پاک کردن build/
```

## چه چیزی را ببینیم

**PASS (30 checks)** در ۵۳۶ نانوثانیه.

- `dut4` از ۰ تا ۹ می‌شمارد، `at_max` را بالا می‌برد و لبهٔ بعد به ۰ می‌پیچد.
- `dut6` از ۰ تا ۴۰ می‌شمارد و مستقل از `dut4` به ۰ می‌پیچد. دو نمونه ساعت و
  ریست مشترک دارند اما در بستر آزمون فعال‌ساز جداگانه.
- `cnt4'length = 4` و `cnt6'length = 6`. یک سورس هر دو را ساخته و بستر آزمون
  با ویژگی‌ها بررسی‌شان می‌کند.
- شمارش پایانی در زمان بسط محاسبه می‌شود. اگر `MAX = 9` را با `WIDTH = 3` بدهی،
  `to_unsigned` در بسط شکست می‌خورد، نه اینکه شمارنده‌ای بسازد که هرگز تطبیق
  نمی‌یابد.

## تمرین‌ها

1. جنریک `STEP : positive := 1` اضافه کن. شرط پیچش را طوری به‌روز کن که
   شمارنده هرگز از `MAX` جلو نزند و بستر آزمون را با `STEP => 3` گسترش بده.
2. نمونهٔ سومی با `MAX => 0` و `WIDTH => 5` بساز. بررسی کن در ۳۱ می‌پیچد.
3. انتساب ریست را با حلقه‌ای روی `cnt'range` عوض کن و تأیید کن رفتار عوض
   نمی‌شود.
4. عمداً بشکن: `WIDTH => 3, MAX => 9` را نمونه‌سازی کن و خطای بسط را بخوان.
   بعد تصمیم بگیر برای طراحی‌های خودت اعلان زمان اجرا بهتر است یا نه.

## راهنما

<details><summary>نمایش راهنماها</summary>

- جنریک‌ها در ناحیهٔ اعلان معماری دیده می‌شوند، از جمله داخل توابعی که آنجا
  اعلان می‌شوند.
- `to_unsigned(MAX, WIDTH)` به `MAX <= 2**WIDTH - 1` نیاز دارد؛ پیش از متهم
  کردن بستر آزمون این را بررسی کن.
- ویژگی‌ها روی درگاه‌ها هم کار می‌کنند (`count'length` داخل موجودیت) و روی
  انواع لیترالی (`integer'image`).
- `generic map` از `=>` استفاده می‌کند، همان نحو انتساب `port map`.

</details>
