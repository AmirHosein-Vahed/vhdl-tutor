# 05 — دستورهای هم‌زمان و ترتیبی

**وضعیت:** نوشته‌شده · **موضوع:** [01-language-basics — مبانی زبان](../README.fa.md) · [English](README.md)

> **آماده.** در همین پوشه `make` را اجرا کن. طراحی `mux_styles` ساخته می‌شود،
> بستر آزمون خودبررسی اجرا می‌شود و در صورت شکست کد خروج غیرصفر برمی‌گردد.

## هدف

ببین که `y <= a and b;` خودش یک فرایند است و `when` / `with` / `case` / `if`
توصیف‌های قابل‌تعویض یک سخت‌افزارند. بینشان بر اساس خوانایی انتخاب کن، نه
رفتار.

## از وریلاگ به VHDL

| وریلاگ / SystemVerilog | VHDL |
|---|---|
| `assign y = s ? b : a;` | `y <= b when s = '1' else a;` |
| `always @(*) case (s) ... endcase` | `process (all) ... case s is ... end case;` |
| `always_comb` | `process (all)` با انتساب پیش‌فرض |
| `assign y = a & b;` | `y <= a and b;` — هم‌زمان، بدون کلیدواژهٔ `assign` |

در VHDL کلیدواژهٔ `assign` وجود ندارد. هر دستور هم‌زمان در بدنهٔ معماری یک
فرایند ضمنی است که هرگاه یکی از ورودی‌هایش تغییر کند اجرا می‌شود. دستورهای
ترتیبی فقط *درون* فرایند وجود دارند.

## مفاهیم

- انتساب سیگنال هم‌زمان معادل فرایندی با فهرست حساسیت درست است. `y <= a and b;`
  و `process (a, b) begin y <= a and b; end process;` یک مدار را توصیف می‌کنند.
- `when`/`else` زنجیرهٔ اولویت است. اولین شرط درست برنده است، پس شاخه‌های بعدی
  یعنی شاخه‌های قبلی نادرست بوده‌اند.
- `with ... select` یک case موازی است: انتخاب‌ها باید جدا و کامل باشند.
  اولویت ندارد؛ هر انتخاب مستقل نگاشت می‌شود.
- `case` درون فرایند زندگی می‌کند، در عمل برای `std_logic_vector` به
  `when others` نیاز دارد و شفاف‌ترین راه نوشتن دیکدر است.
- `process (all)` (VHDL-2008) فهرست حساسیت را از بدنه استخراج می‌کند و باگ
  کلاسیک «یک ورودی را فراموش کردی، شبیه‌سازی قبول شد، سنتز فرق کرد» را
  جلوگیری می‌کند.
- هر شاخه باید خروجی را مقدار بدهد، وگرنه لچ استنباط می‌شود. انتساب پیش‌فرض
  در ابتدای فرایند نگهبان معمول است.

## اجرا

```bash
make        # تحلیل، بسط و اجرای بستر آزمون خودبررسی
make wave   # همان، به‌همراه نوشتن build/mux_styles_tb.ghw
make clean  # پاک کردن build/
```

## چه چیزی را ببینیم

**PASS (19 checks)** در ۵ نانوثانیه. هر مقدار انتخاب همان بایت را روی
`y_when`، `y_with` و `y_case` تولید می‌کند و بستر آزمون توافق سه خروجی با هم
را هم بررسی می‌کند.

- `sel = "11"` به شاخهٔ آخر `else` / `when others` می‌افتد. تنها شاخه‌ای است که
  طراحی را کامل نگه می‌دارد.
- `with sel select` جدول جست‌وجوست، نه زنجیرهٔ اولویت. در `when`/`else`
  جابه‌جایی شاخه‌ها می‌تواند رفتار را عوض کند؛ در `with`/`select` هر انتخاب
  مستقل است.
- فرایند در سورس اصلاً فهرست حساسیت ندارد؛ `(all)` همان چیزی است که درستی‌اش
  را حفظ می‌کند.

## تمرین‌ها

1. ورودی `valid` اضافه کن. وقتی `'0'` است هر سه خروجی باید صفر باشند. رفتار
   سه سبک را یکسان نگه دار.
2. `case` را با `if`/`elsif`/`else` عوض کن و تأیید کن بستر آزمون هنوز قبول
   می‌شود.
3. `when others` را از `with`/`select` حذف کن و خطای کامپایلر را بخوان. همین
   کار را با `case` بکن و تفاوت دو پیام را ببین.
4. انتساب پیش‌فرض را ابتدای فرایند اضافه کن، بعد یک شاخه را حذف کن. توضیح بده
   شاخهٔ غایب چه سخت‌افزاری استنباط می‌کند.

## راهنما

<details><summary>نمایش راهنماها</summary>

- `process (all)` مال VHDL-2008 است؛ ساخت با `--std=08` اجرا می‌شود.
- انتساب انتخابی برای هر مقدار ممکن انتخاب‌گر به یک گزینه نیاز دارد.
  `when others` بقیه را پوشش می‌دهد.
- `y <= (others => '0');` به‌عنوان اولین دستور فرایند، روش استاندارد پرهیز از
  لچ است.

</details>
