# ۰۷ — آگاهی از سنتز

شبیه‌سازی پاسخ می‌دهد «آیا منطق همان کاری را می‌کند که منظورم بود؟». سنتز پاسخ
می‌دهد «چه سخت‌افزاری از آن ساخته می‌شود؟». برای یادگیری سؤال دوم به بورد FPGA
نیاز نداری، اما باید بدانی کدام کد معنای سخت‌افزاری ندارد.

این سند هم‌راه موضوع ۱۰ است.

---

## زیرمجموعهٔ سنتزپذیر

| ساختار | سنتزپذیر؟ | توضیح |
|---|---|---|
| `entity`، `architecture`، `port`، `generic` | بله | هستهٔ زبان |
| انتساب هم‌زمان، `when`، `with` | بله | مالتی‌پلکسر/منطق می‌شود |
| `process` با `if`/`case`/حلقه | بله | حلقه‌ها باز می‌شوند |
| `rising_edge` / `falling_edge` | بله | تنها آزمون ساعت |
| ریست هم‌زمان / ناهم‌زمان | بله | وابسته به الگو |
| `for generate`، `if generate` | بله | تکرار در زمان بسط |
| تابع و رویه | بله | باید ترکیبی خالص باشد |
| بسته، رکورد، شمارشی | بله | رکورد در درگاه سطح بالا وابسته به ابزار |
| مقدار اولیهٔ سیگنال | وابسته به ابزار | FPGA بله، ASIC نه |
| تأخیر `after` | **نه** | نادیده گرفته یا رد می‌شود |
| `wait for`، `wait on` | **نه** | `wait until rising_edge` درون فرایند یعنی ساعت |
| `textio`، `file` | **نه** | فقط بستر آزمون |
| `report` برای رفتار | **نه** | ادعاها ممکن است برای جریان صوری بمانند |
| حساب `real` و `time` | **نه** | عدد صحیح یا ممیز ثابت به کار ببر |
| تقسیم بر غیرثابت | معمولاً نه | تقسیم‌کنندهٔ IP یا الگوریتم تکراری |
| نوع دسترسی (اشاره‌گر) | نه | برای RTL نیست |
| `'image`، `'value` | نه | پردازش رشته سخت‌افزار ندارد |
| `std.env.finish` | نه | کنترل شبیه‌سازی |
| ادعاهای PSL در توضیحات | نادیده | برای جریان صوری مفید |

الگو: **هر چیزی که به زمان واقعی یا نرم‌افزار میزبان وابسته است، فقط
شبیه‌سازی است.** هر چیزی که تابعی از ورودی‌های جاری و حالت ذخیره‌شده باشد
می‌تواند سخت‌افزار شود.

## کد تو چه می‌سازد

| الگوی RTL | سخت‌افزار |
|---|---|
| `y <= a when s = '1' else b;` | مالتی‌پلکسر ۲ به ۱ (LUT) |
| `case sel is ...` با N شاخه | درخت مالتی‌پلکسر یا یک LUT برای هر بیت |
| `a + b` روی `unsigned` | زنجیرهٔ نقلی |
| `a * b` با ثابت | شیفت و جمع (اغلب رایگان) |
| `a * b` با متغیر | بلوک DSP یا ضرب‌کنندهٔ بزرگ |
| شیفت با ثابت | سیم‌کشی، هزینهٔ صفر |
| شیفت با متغیر | شیفت‌رجیستر بشکه‌ای (درخت مالتی‌پلکسر) |
| `if rising_edge(clk)` با `en` | فلیپ‌فلاپ با مالتی‌پلکسر فعال‌ساز |
| آرایه با نوشتن هم‌زمان و خواندن هم‌زمان | بلوک RAM |
| آرایه با خواندن ناهم‌زمان | RAM توزیع‌شده / LUT RAM |
| آرایه بدون ریست و خواندن ناهم‌زمان | ROM (اگر هرگز نوشته نشود) |
| `if` بدون `else` در کد ترکیبی | **لچ** |
| دو فرایند ساعت‌دار با دو ساعت مختلف | دو دامنه؛ نیازمند CDC |

دو مورد پررنگ باگ‌های واقعی می‌سازند: لچ و دامنهٔ ساعت. بقیه مسئلهٔ سطح و سرعت
است.

## جریان Yosys

Yosys و افزونهٔ GHDL را نصب کن:

```bash
sudo apt install yosys
git clone https://github.com/ghdl/ghdl-yosys-plugin
cd ghdl-yosys-plugin
make            # به ghdl و هدرهای yosys نیاز دارد
sudo make install
```

سپس از پوشهٔ درسی که `src/` سنتزپذیر دارد:

```bash
make synth
```

که این را اجرا می‌کند:

```bash
yosys -m ghdl -p "ghdl --std=08 --workdir=build and2; synth; stat"
```

هدف `make synth` ابتدا منابع را با GHDL تحلیل می‌کند و سپس از افزونهٔ Yosys
می‌خواهد واحدی را که از قبل در `build/` هست elaborates کند. اگر GHDL را از
tarball قابل‌جابه‌جایی نصب کرده‌اید (نه از بستهٔ توزیع)، `GHDL_PREFIX` را تنظیم
کنید (مثلاً `~/.local/opt/ghdl-6.0.0/lib/ghdl`) تا libghdl کتابخانه‌های `std`
و `ieee` را پیدا کند.

گزارش چه می‌گوید:

```
=== and2 ===

   Number of wires:                  1
   Number of cells:                  1
     $_AND_                          1
```

برای طراحی بزرگ‌تر، شمارش به تفکیک نوع سلول می‌آید: `$_DFF_P_` (فلیپ‌فلاپ لبهٔ
بالا)، `$_MUX_`، `$_AND_`، `$_XOR_`، `$mem` (حافظه)، `$_DFF_PP0_` (ریست) و
غیره. این‌ها گیت‌های عمومی‌اند، نه LUT یک FPGA خاص، اما اعداد *نسبی* هنوز
آموزنده‌اند:

- شمارنده باید زنجیرهٔ نقلی و W فلیپ‌فلاپ نشان دهد،
- مالتی‌پلکسر باید برای هر بیت و هر خط انتخاب یک `$_MUX_` نشان دهد، نه لچ،
- RAM باید سلول `$mem` نشان دهد، نه هزاران گیت،
- لچ به‌صورت `$_DLATCH_*` ظاهر می‌شود که تقریباً همیشه باگ است.

برای دیدن شبکه به‌جای شمارش:

```bash
yosys -m ghdl -p "ghdl --std=08 src/alu.vhd -e alu; synth; write_json build/alu.json"
netlistsvg build/alu.json -o build/alu.svg
```

`netlistsvg` یک ابزار کوچک Node است؛ `dot` از Graphviz هم کار می‌کند.

## خواندن هشدارهای سنتز

پیام‌هایی که مهم‌اند، به ترتیب:

1. **«Latch inferred»** — فرایند ترکیبی در همهٔ مسیرها خروجی را مقدار نمی‌دهد.
   RTL را درست کن؛ هشدار را خفه نکن.
2. **«Port has no driver»** — سیگنالی هرگز مقدار نمی‌گیرد. در شبیه‌سازی `'U'`
   می‌ماند و در سخت‌افزار به مقدار ثابت بسته می‌شود.
3. **«Multiple drivers»** — دو فرایند یک سیگنال را می‌رانند. فقط با نوع حل‌شده و
   سه‌حالته قانونی است و به‌ندرت همانی است که می‌خواستی.
4. **«Combinational loop»** — منطق به خودش وابسته است. شبیه‌سازی ممکن است همگرا
   شود؛ سخت‌افزار نه.
5. **«Ignoring initial value»** — جریان ASIC؛ ریست اضافه کن.
6. **«Found and optimized away»** — منطق مرده. گاهی بی‌خطر است، گاهی نشانهٔ
   اینکه خروجی‌ات هرگز خوانده نمی‌شود.

## آنچه این دوره پوشش نمی‌دهد

عمداً خارج از محدوده، چون به سخت‌افزار و ابزار فروشنده نیاز دارد:

- قید پایه‌ها و استانداردهای ورودی/خروجی،
- قید ساعت، بستن زمان‌بندی و قیدهای `false_path`/CDC،
- تولید بیت‌استریم،
- ریست و ساعت در سطح بورد،
- تحلیل توان.

اگر بعداً FPGA را هدف بگیری، همان RTL کار می‌کند؛ چیزی که اضافه می‌کنی فایل
قید و یک اجرای سنتز مخصوص فروشنده است. مفاهیم موضوع ۱۰ — استنتاج، لچ، حافظه،
CDC — بدون تغییر منتقل می‌شوند.

---

## چک‌لیست سلامت پیش از سنتز

- [ ] هر `process` با `rising_edge` دقیقاً یک ساعت دارد.
- [ ] هر فرایند ترکیبی در هر مسیر همهٔ خروجی‌ها را مقدار می‌دهد.
- [ ] هیچ `after`، `wait for`، `textio` یا `real` در `src/` نیست.
- [ ] هر درگاه راه‌اندازی شده است.
- [ ] هر آرایه‌ای که باید RAM باشد در فرایند ساعت‌دار نوشته و خوانده می‌شود.
- [ ] بازخورد ترکیبی وجود ندارد.
- [ ] مقدار ریست برای همهٔ رجیسترهای حالت تعریف شده است.
- [ ] طراحی پس از آخرین ویرایش هنوز `make` را پاس می‌کند.
