# ۰۴ — دام‌ها

این‌ها اشتباهاتی هستند که واقعاً رخ می‌دهند، تقریباً به ترتیب شیوع. هر کدام نسخهٔ
غلط، دلیل غلط‌بودن و راه‌حل را دارد.

---

## ۱. حساب روی `std_logic_vector`

```vhdl
signal a, b, y : std_logic_vector(7 downto 0);
y <= a + b;                       -- کامپایل نمی‌شود
```

`std_logic_vector` آرایه‌ای از بیت‌های ۹مقداری است، نه عدد. عملگر `+` برای آن
تعریف نشده.

```vhdl
use ieee.numeric_std.all;
y <= std_logic_vector(unsigned(a) + unsigned(b));   -- ۸ بیتی: نقلی گم می‌شود
```

اگر نقلی مهم است، نتیجه را پهن‌تر کن:

```vhdl
signal sum : unsigned(8 downto 0);
sum <= ('0' & unsigned(a)) + ('0' & unsigned(b));
```

---

## ۲. لچ ناخواسته

```vhdl
process (all)
begin
  if en = '1' then
    y <= a;              -- وقتی en = '0' است، y مقدار نمی‌گیرد
  end if;
end process;
```

ابزار باید وقتی `en = '0'` است `y` را نگه دارد، پس لچ می‌سازد. سنتز هشدار
می‌دهد؛ شبیه‌سازی با خوشحالی اجرا می‌شود و همین باعث می‌شود تا سخت‌افزار زنده
بماند.

```vhdl
process (all)
begin
  y <= '0';              -- همهٔ مسیرها y را مقدار می‌دهند
  if en = '1' then
    y <= a;
  end if;
end process;
```

یک `case` بدون `when others` همان باگ در لباس دیگر است.

---

## ۳. فهرست حساسیتی که با بدنه نمی‌خواند

```vhdl
process (a)              -- b جا افتاده
begin
  y <= a and b;
end process;
```

شبیه‌سازی تغییرهای `b` را نادیده می‌گیرد؛ سنتز فهرست را نادیده می‌گیرد و گیت
درست را می‌سازد. این دو با هم اختلاف دارند و تو دنبال یک شبح می‌گردی.

در VHDL-2008 از `process (all)` استفاده کن. اگر مجبور به VHDL-93 هستی، هر سیگنالی
را که فرایند می‌خواند — از جمله داخل رویه‌ها — فهرست کن.

فرایند ساعت‌دار متفاوت است: فقط `clk` (و برای ریست ناهم‌زمان `rst`) در فهرست
می‌آید. آوردن سیگنال‌های داده هم آنجا یک باگ است.

---

## ۴. سیگنال در برابر متغیر در یک فرایند

```vhdl
process (clk)
begin
  if rising_edge(clk) then
    a <= b;
    c <= a;              -- c مقدار قبلی a را می‌گیرد
  end if;
end process;
```

هر دو سمت راست با مقدارهای پیش از لبه ارزیابی می‌شوند و هر دو به‌روزرسانی در یک
دلتا رخ می‌دهد. برای شیفت‌رجیستر معمولاً همین را می‌خواهی و برای کد نرم‌افزاری
معمولاً نه.

```vhdl
process (clk)
  variable tmp : std_logic;
begin
  if rising_edge(clk) then
    tmp := b;
    c   <= tmp;          -- مقدار جدید را می‌بیند
  end if;
end process;
```

متغیر در فرایند ساعت‌دار قانونی و گاهی مفید است، اما رجیسترها را از چشم خواننده
پنهان می‌کند. سیگنال را ترجیح بده؛ متغیر فقط برای مقادیر میانی ترکیبی.

---

## ۵. تأخیر «فقط یک دلتا»

```vhdl
a <= '1';
wait for 0 ns;          -- تضمین نمی‌کند a به‌روز شده باشد
b <= a;
```

`wait for 0 ns` یک واگذاری چرخهٔ دلتاست و تعداد دلتاهای لازم برای به‌روزرسانی
سیگنال چیزی نیست که به آن تکیه کنی. اگر ترتیب می‌خواهی، برای زمان واقعی صبر کن
(`wait for 1 ns`) یا محرک را بازطراحی کن.

---

## ۶. عدد صحیح بدون بازه

```vhdl
signal count : integer;         -- ۳۲ بیتی علامت‌دار، در 2**31-1 می‌چرخد
count <= count + 1;             -- بی‌صدا می‌چرخد
```

زیرنوع محدود یا بردار unsigned را ترجیح بده:

```vhdl
signal count : integer range 0 to 4095;
signal count : unsigned(11 downto 0);
```

بازه در بسط و (برای سیگنال‌ها) در زمان اجرا بررسی می‌شود و چرخش را به خطا تبدیل
می‌کند.

---

## ۷. مقایسه میان انواع

```vhdl
if slv = 5 then ...                       -- غیرمجاز
if unsigned(slv) = to_unsigned(5, 8) then -- مجاز و صریح
if slv = std_logic_vector(to_unsigned(5, 8)) then  -- مجاز و پرحرف
```

تبدیل ضمنی وجود ندارد. این همان نکته است، اما بستر آزمون را پرحرف می‌کند.
کمک‌تابع‌های `tb_utils` (`check_eq` برای `unsigned` و `integer`) برای همین
هستند.

## ۸. گم‌شدن بیت‌ها در جمع و ضرب

```vhdl
signal a, b : unsigned(7 downto 0);
signal y    : unsigned(7 downto 0);
y <= a * b;                    -- ۸ بیت از حاصل ۱۶ بیتی: بریده می‌شود
```

ضرب دو عملوند W بیتی به 2W بیت نیاز دارد. جمع اگر نقلی مهم است به W+1 بیت نیاز
دارد. کامپایلر هشدار نمی‌دهد؛ نتیجه فقط غلط است.

```vhdl
signal p : unsigned(15 downto 0);
p <= a * b;
```

برای مقدارهای علامت‌دار یادت باشد `resize` گسترش علامت می‌دهد و برش ساده نمی‌دهد:

```vhdl
y <= resize(signed(a), 16);            -- گسترش علامت
y <= signed(a) & x"00";                -- گسترش صفر، احتمالاً باگ
```

## ۹. پخش‌شدن `'U'`

`'U'` یعنی «مقدارنگرفته». سیگنال `std_logic` که هرگز راه‌اندازی نشود `'U'`
می‌ماند و هر گیتی که به آن برسد `'U'` می‌شود.

علت‌های رایج:

- بستر آزمون هیچ‌وقت ورودی را مقدار نمی‌دهد،
- اتصال درگاه جا افتاده یا غلط نوشته شده (اتصال نام‌دار جلوی این را می‌گیرد)،
- سیگنال اعلان شده اما فقط در `if`ای مقدار می‌گیرد که هرگز رخ نمی‌دهد،
- ریست اعمال نشده است.

این یک مزیت است: `'U'` روی خروجی در ۱۰۰ نانوثانیهٔ اول می‌گوید طراحی ناقص است،
نه اینکه شبیه‌ساز خراب است.

## ۱۰. گیت‌کردن ساعت

```vhdl
gated_clk <= clk and en;        -- این کار را نکن
```

دامنهٔ ساعت جدید می‌سازد، تحلیل زمان‌بندی را می‌شکند و گلیچ تولید می‌کند.
از فعال‌ساز ساعت استفاده کن:

```vhdl
process (clk)
begin
  if rising_edge(clk) then
    if en = '1' then
      q <= d;
    end if;
  end if;
end process;
```

## ۱۱. مقدار اولیه به‌جای ریست

```vhdl
signal state : state_t := IDLE;
```

در شبیه‌سازی و روی بیشتر FPGAها کار می‌کند (ابزار رجیستر را هنگام پیکربندی
مقداردهی می‌کند). در سنتز ASIC کار نمی‌کند و از خرابی ناشی از گلیچ نجاتت
نمی‌دهد. برای هر چیز مهم ریست واقعی بگذار و مقدار اولیه را فقط راحتی شبیه‌سازی
بدان.

مرتبط: رهاسازی ریست ناهم‌زمان، ناهم‌زمان است. اگر نزدیک لبهٔ ساعت رها شود، اولین
رجیستر می‌تواند فرامانده شود. همگام‌ساز ریست دو فلیپ‌فلاپی حلش می‌کند؛ موضوع
۰۳/۰۲.

## ۱۲. کد مخصوص شبیه‌سازی در RTL سنتزپذیر

```vhdl
y <= a after 5 ns;          -- سنتز نادیده می‌گیرد
```

همچنین: `wait for`، `textio` در RTL، `report` برای رفتار، حساب `real`، تقسیم بر
غیرثابت و ورودی/خروجی فایل.

قاعده: اگر برای رفتارش به ساعت یا تأخیر نیاز دارد، جای آن بستر آزمون است، نه
`src/`.

---

## ۱۳. بستر آزمونی که می‌تواند معلق بماند

```vhdl
wait until ack = '1';       -- اگر DUT خراب باشد، همیشه
```

هر بستر آزمون در این دوره دو چیز دارد:

- نگهبان: فرایند موازی که پس از `TIMEOUT` شکست گزارش می‌کند،
- `--stop-time` روی خط فرمان شبیه‌ساز، به‌عنوان آخرین سد دفاعی.

```vhdl
watchdog : process
begin
  wait for TIMEOUT;
  report "timeout: ack never arrived" severity failure;
end process;
```

## ۱۴. استفاده از `bit` چون ساده‌تر به نظر می‌رسد

`bit` دو مقدار دارد و حل‌شدگی ندارد. نمی‌تواند تعارض گذرگاه، شبکهٔ
راه‌اندازی‌نشده یا سه‌حالته را بیان کند. برای هر سیگنالی که به درگاه یا گذرگاه
می‌رسد از `std_logic` استفاده کن. `bit`/`bit_vector` برای ثابت‌های داخلی خالص
خوب‌اند و حتی همان‌جا هم `std_logic` هزینه‌ای ندارد.

---

## ۱۵. فراموش‌کردن اینکه `=` روی آرایه‌ها عرض را هم مقایسه می‌کند

```vhdl
signal a : std_logic_vector(7 downto 0);
constant C : std_logic_vector(3 downto 0) := x"F";
if a = C then ...            -- همیشه نادرست: ۸ بیت در برابر ۴ بیت
```

VHDL برایت گسترش صفر نمی‌دهد. این باگ رایج بستر آزمون است وقتی لیترال از سیگنال
کوتاه‌تر است. اندازه‌اش را صریح کن:

```vhdl
if a = x"0F" then ...
```
