# ۰۲ — چرخهٔ کار: تحلیل، بسط، اجرا

GHDL سه ابزار در یک فایل است و این تقسیم مهم است.

| مرحله | فرمان | کار | خروجی |
|---|---|---|---|
| تحلیل | `ghdl -a file.vhd` | تجزیه و بررسی نوع یک واحد طراحی، نوشتن در کتابخانه | `work-obj08.cf` |
| بسط | `ghdl -e top` | ساخت سلسله‌مراتب، تعیین جنریک‌ها، اتصال درگاه‌ها | مدل اجرایی |
| اجرا | `ghdl -r top` | شبیه‌سازی | متن خروجی و شکل موج اختیاری |

می‌توانی هر سه را دستی اجرا کنی — وقتی `make` چیزی را پنهان می‌کند مفید است:

```bash
cd 00-hello-world/01-first-entity-and-testbench
mkdir -p build
ghdl -a --std=08 --workdir=build ../../common/vhdl/tb_utils.vhd
ghdl -a --std=08 --workdir=build src/and2.vhd
ghdl -a --std=08 --workdir=build tb/and2_tb.vhd
ghdl -e --std=08 --workdir=build and2_tb
ghdl -r --std=08 --workdir=build and2_tb --assert-level=error --stop-time=1ms
```

`--workdir` همهٔ فایل‌های تولیدشده را در `build/` نگه می‌دارد، پس درخت سورس تمیز
می‌ماند و `make clean` ساده است.

## `make` چه می‌کند

هر درس یک Makefile دوخطی دارد:

```make
# All build logic lives in common/exercise.mk.
include ../../common/exercise.mk
```

`common/exercise.mk` فایل‌های `src/*.vhd` و `tb/*.vhd` را پیدا می‌کند، اولین
`*_tb.vhd` را به‌عنوان سطح بالا برمی‌دارد و `analyze → elab → run` را اجرا می‌کند.

```bash
make                  # کل چرخه
make analyze          # فقط بررسی نحو و نوع؛ سریع‌ترین بازخورد
make elab             # فقط سلسله‌مراتب
make run              # اجرا بدون تحلیل دوباره (وابستگی‌ها بررسی می‌شوند)
make wave             # اجرا با ‎--wave=build/<top>.ghw و باز کردن نمایشگر
make vcd              # اجرا با ‎--vcd=build/<top>.vcd
make synth            # Yosys و افزونهٔ GHDL (موضوع ۱۰)
make help             # نمایش متغیرهای مؤثر
make clean            # پاک کردن build/
```

متغیرهای قابل تغییر:

| متغیر | پیش‌فرض | کاربرد |
|---|---|---|
| `GHDL` | `ghdl` | نسخه یا پوشش دیگر شبیه‌ساز |
| `STD` | `08` | `STD=93` برای بررسی سازگاری با VHDL-93 |
| `TOP` | اولین `*_tb.vhd` | چند بستر آزمون در یک درس |
| `STOP_TIME` | `1ms` | شبیه‌سازی‌های طولانی |
| `RUN_ARGS` | خالی | `-gWIDTH=16 --ieee-asserts=disable` |
| `WAVE_VIEWER` | surfer، سپس gtkwave | اجبار یک نمایشگر مشخص |

مثال‌ها:

```bash
make TOP=fifo_full_tb STOP_TIME=10ms
make RUN_ARGS="-gWIDTH=32 -gDEPTH=64"
make wave WAVE_VIEWER=gtkwave
```

## کد خروج و CI

اگر تحلیل، بسط یا بستر آزمون شکست بخورد، `make` با کد غیرصفر خارج می‌شود. همین
کل قرارداد است و به همین دلیل هر درس با یک فرمان قابل رگرسیون‌آزمایی است:

```bash
make test              # همهٔ درس‌های done یا draft
make test-all          # هر درسی که کد دارد
make test-07-memories  # یک موضوع
make test -v           # نمایش خروجی شبیه‌ساز در شکست
```

جزئیات GHDL که این را ممکن می‌کند:

- `--assert-level=error` شبیه‌سازی را در هر `severity error` یا بالاتر متوقف
  می‌کند. بستهٔ کمکی دوره شکست‌های تکی را `warning` گزارش می‌کند تا همهٔ بردارها
  بررسی شوند و خلاصه را `failure`.
- `--stop-time` تضمین می‌کند اجرا تمام شود، حتی اگر بستر آزمون `std.env.finish`
  را فراموش کند.
- `std.env.finish` فایل شکل موج را پیش از خروج می‌بندد، پس `make wave` رد کامل
  تولید می‌کند.

اجرای موفق:

```
== analyze 08 ==
== elaborate and2_tb ==
== run and2_tb ==
and2_tb: PASS (4 checks)
```

اجرای ناموفق:

```
FAIL: 1 and 1 (expected '0', got '1')
and2_tb: FAIL (1 of 4 checks failed)
ghdl:error: report failed
make: *** [run] Error 1
```

## شکل موج

```bash
make wave
```

فایل `build/<top>.ghw` را می‌نویسد و نمایشگر را باز می‌کند. GHW اطلاعات کامل نوع
را نگه می‌دارد: شمارشی‌ها با نام، `std_logic` با نُه مقدارش و رکوردها بازشده.
VCD همه‌چیز را به بیت تخت می‌کند — فقط برای تبادل با ابزارهای دیگر به کار ببر.

ترتیب پیشنهادی سیگنال‌ها روی رد:

1. ساعت و یک نشانگر مشتق از ساعت،
2. ریست و فعال‌ساز،
3. همهٔ سیگنال‌های حالت (اگر شمارشی باشند، `IDLE` و `RUN` را می‌بینی)،
4. ورودی‌ها و خروجی‌های DUT،
5. رجیسترهای میانی خط لوله هنگام اشکال‌زدایی زمان‌بندی.

دو عادت ارزشمند:

- **همیشه ۱۰۰ نانوثانیهٔ اول را ببین.** مقدار ریست، `'U'` روی سیگنال‌های
  راه‌اندازی‌نشده و اولین لبهٔ ساعت بیشتر مشکلات را نشان می‌دهند.
- **به دلتا زوم کن، نه به نانوثانیه.** وقتی دو سیگنال در یک زمان تغییر می‌کنند
  اما `report` مقدار قبلی را نشان می‌دهد، پاسخ در ترتیب است، نه در زمان.

فایل GHW را بعداً روی هر ماشینی با GTKWave یا Surfer می‌توان باز کرد:

```bash
gtkwave build/and2_tb.ghw
surfer build/and2_tb.ghw
```

## ترتیب اشکال‌زدایی

وقتی درسی شکست می‌خورد، در برابر وسوسهٔ تغییر فوری RTL مقاومت کن.

1. **اولین بررسی شکست‌خورده را بخوان.** مقدار انتظاری و واقعی را چاپ می‌کند.
2. **زمان را ببین.** شکست در زمان صفر معمولاً سیگنال مقدارنگرفته یا ریستی است
   که اعمال نشده.
3. **همه‌جا `'U'`؟** یک درگاه راه‌اندازی نشده. جهت‌های port map و بستر آزمون را
   بررسی کن.
4. **مقدار یک چرخه عقب است؟** سیگنال در برابر متغیر، یا چرخهٔ دلتا.
5. **فقط در مرز غلط است؟** عرض، گسترش علامت یا بازهٔ یکی‌کم/بیش.
6. **بعد** شکل موج را ببین — با نشانگر روی زمان همان بررسی شکست‌خورده.

سطوح severity از کم‌خطر به «لطفاً توقف»:

```vhdl
report "..." severity note;     -- دیده می‌شود، بی‌خطر
report "..." severity warning;  -- دیده می‌شود، متوقف نمی‌کند
report "..." severity error;    -- با --assert-level=error متوقف می‌کند
report "..." severity failure;  -- همیشه متوقف می‌کند
```

`report` بدون شرط همیشه چاپ می‌کند؛ `assert cond report msg` فقط وقتی `cond`
نادرست است چاپ می‌کند — یعنی برعکس `assert` در تست نرم‌افزار. هنگام خواندن بستر
آزمون دیگران این را به یاد داشته باش.

## یک جلسهٔ کاری معمولی

```bash
make list                          # امروز چه کار کنم؟
cd 03-sequential/01-first-clocked-process
make analyze                       # بررسی سریع نوع هنگام ویرایش
make                               # اجرای آزمون‌ها
make wave                          # فقط وقتی بررسی شکست خورد و زمان مهم است
make clean                         # پیش از کامیت، تا build/ وارد git نشود
```

سپس از ریشهٔ مخزن:

```bash
make test                          # همه‌چیز سبز است؟
make check-i18n                    # README فارسی را فراموش نکردم؟
```
